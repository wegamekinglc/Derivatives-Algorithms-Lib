# Fixings JSON benchmark

`json_perf` is an informational core target, outside the nine-target regression
gate. It links only `DAL::cpp` and works with the public component disabled.
Configure from the repository root:

```bash
cmake --preset=Release-linux -S . -B build/core-bench \
  -DDAL_CPP_BUILD_BENCHMARKS=ON -DDAL_CPP_BUILD_EXAMPLES=OFF \
  -DDAL_CPP_BUILD_TESTS=OFF -DDAL_BUILD_PUBLIC=OFF \
  -DDAL_BUILD_PYTHON=OFF -DDAL_BUILD_EXCEL=OFF \
  -DDAL_BUILD_EXCEL_PORTABLE_TESTS=OFF
cmake --build build/core-bench --target json_perf interp_perf --parallel 4
DAL_NUM_THREADS=1 build/core-bench/dal-cpp/benchmarks/json_perf/json_perf --preflight
DAL_NUM_THREADS=1 build/core-bench/dal-cpp/benchmarks/json_perf/json_perf
```

Default output retains the common Bench columns and five rows:

| Case | Input |
|---|---|
| `fixings-write-1` / `fixings-write-365` | Prebuilt Fixings with 1/365 daily midnight keys from 2025-01-01 and exact binary values `100+i/8` |
| `fixings-read-own-1` / `fixings-read-own-365` | Current writer's prebuilt strings for those same objects |
| `fixings-read-legacy-365` | Fixed historical 365-key bytes embedded in `legacyfixings.hpp` |

Fixture construction, encoding read inputs and validation occur outside timing;
there is no file IO. Each write includes destruction of its returned string,
and each read includes destruction of its returned object. There are two untimed
batches and ten measured batches after doubling to at least 10ms, capped at
65,536 calls. `PROFILE_SAMPLES` preserves raw batch times and inner loop counts;
Bench columns show per-call median/min/max.

Every fixture is checked for exact map equality and per-key LookupFixing.
Preflight additionally checks six precise keys (midnight, smallest subnormal,
two subseconds, nextafter and end-of-day) and stable rewrites. These are
correctness-only inputs; lossy historical subsecond performance is not compared.

The embedded 10,661 bytes are the original batch256 `base-365.json` emitted by
producer `6a194df2`, not generated by a current or legacy compatibility writer
at run time. SHA-256 is
`669a3e27b868e138edefa5fcfb9db5c9e56085163a9837fbf15243ae03e52ada`;
preflight checks this exact byte identity before reading. Preserve the bytes
when future writers change. `read-own` includes format/payload migration costs;
only fixed-legacy reading compares equal bytes across readers.

Use two rounds of ten alternating fresh processes per side, minimum reductions
and the repository's noise controls for comparisons. Keep construction, IO,
other storables/Cell matrices and multiworker behavior separate. A new target
does not resolve or waive the historical same-byte reader regression, and no
production optimization is included here.
