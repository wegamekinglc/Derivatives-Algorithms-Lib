# DAL-451 fixed profile and outer one-shot candidate

This private worker-free entry accepts `profile`, `verify` or `init`. It does not
authorize products, MC, RNG, compilers, workers or a successor. Facility,
H_exact/H_exclude and all financial flags remain false. Current source, shared
process dependency and startup identities need fresh independent acceptance;
older expected profiles and lifecycle observations do not qualify this version.

Startup captures actual module code and compares it with source compilation.
A source-only importer bypasses caches for later Python dependencies, including
the shared process module. Initial source/cache code and available functions are
checked under the fixed-CPython, immutable-install and faithful-loader
assumptions. Audit events, mapped libraries, interpreter, environment and cwd are
retained. Shared deterministic code fingerprints include nested code and sorted
frozensets without executable-object serialization.

An external trusted caller must already hold the actual engineering allocation.
`budget.json` is a local capacity fixture with exact integer fields `wall`,
`cpu`, `bytes`, `files`, requiring at least 4 wall/6 core-seconds, 796672 bytes and 13
slots. It is not an authenticated transfer from a real shared ledger. A private
root gets permanent `outer.pending` before its single helper, followed by the
complete output reservation. No deletion, retry, new root or fixture clone may
refund a real reservation.

The existing thirteen slots and per-slot capacities remain unchanged. Writes
consume their slots before exclusive no-follow open, then fsync file/directory.
Unused source/package/fixture/meter slots are capacity, not proof that authoring
or publication writes have been measured. The caller separately owns the cost
and provenance of inputs and the new immutable shared process source.

The observer has 128 MiB AS and a 2 second hard CPU limit; the helper inherits AS
and lowers hard CPU to 1 second. Shared dispatch fixes `/usr/bin/python3 -I -S -B`, the exact
profile source, mode/root and sealed parent/source-bound ticket before spawning.
The native argument vector is literal; sealed bootstrap/config/source/ticket
descriptors carry the selected invocation, with explicit source/hash, parent
and cwd checks. Receipts retain both the OS vector and logical intent with
bootstrap/config hashes. Explicit file actions close unrelated descriptors. It uses no shell, inherited
interpreter or Python pre-exec callback. The original observer owns the helper's
PID, pipe and final wait4. The conditional address-space sum remains 256 MiB;
startup, allocator/observer ancestry and complete RSS/resource closure remain
separate obligations.

`init`/`verify` require independently reviewed `expected-profile.json` and
`expected-observer.json`; `profile` cannot approve itself. The helper can only
load fixed captured source and invoke ledger initialization, never the inner
worker path. Its sealed ticket is checked both before spawn and in child entry.
Log persistence failures preserve an already acquired wait4 without a second
reap. Partial or missing evidence prevents continuation.

Direct profile controls cover source/cache mismatch, exhausted capacity,
permanent pending, poisoned writes, invalid modes/tickets and logging failures.
Dispatch controls cover fixed interpreter selection, sealed input rejection,
descriptor isolation and failure cleanup. Synthetic worker exit 0/7 and launcher
init regressions are separate from a real outer profile/init/verify approval.
No real shared allocation was consumed, and no old failure or UNKNOWN was erased.
