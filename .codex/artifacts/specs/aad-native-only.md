# DAL 原生 AAD 唯一实现规格

状态：外部支持移除与原生简化已在独立开发源码实施，正在验收。
本地完整功能与配对性能按既有政策通过；发布提交 `b42f9eb` 的 28 项 CI 和逐项审计通过，D00 已验收。
这不代表完整阶段 A 或整个 AAD 方案已经完成。

来源：用户在本次完整 AAD 开发中明确要求移除 XAD、CoDiPack 和 Adept 支持，简化代码，仅保留内置原生 AAD。
本规格优先于早期方案中的四后端兼容、外部适配、外部标量回退和跨后端验收要求。
工作编号为 D00，属于阶段 A；D03 改为原生操作契约，后续 F/P/D 功能全部使用原生 AAD。

## 目标与范围

完成后的 DAL 只有原生 `Number_`、表达式模板、节点和 tape 实现。
普通配置、诊断配置、示例、C++ 安装包、Python 和 Excel 均不获取、编译、链接或导出三项外部 AAD 库。
保留已有原生数值修复、录制作用域、诊断开关、向量通道和生产性能保障。

本次移除允许外部后端用户的构建配置及相关类型兼容性发生显式变化。
保留原生 C++/Python/Excel 估值入口、风险单位、路径编号、归约与 LSM 策略语义。
不承诺已发布外部后端二进制与原生库 ABI 兼容；迁移须重新配置、重新编译库及消费者。
不删除不相关依赖，不改动独立性能基线中的历史源码或原始证据。

## 要求

R01. 删除 `aad.hpp/.cpp`、`expr.hpp`、`node.hpp`、`tape.hpp/.cpp` 等生产文件的外部后端实现、
include、类型别名、条件分支和仅供这些实现使用的辅助代码。
原生分支成为直接实现；仅为排除外部后端存在的原生条件编译保护一并清理。
诊断开关和有独立用途的平台条件编译继续保留。

R02. 删除 `.gitmodules` 中 `dal-cpp/externals/xad`、`dal-cpp/externals/CodiPack`、
`dal-cpp/externals/adept` 三个条目及对应 Git gitlink。
全新 checkout 初始化剩余子模块后即可完成构建；不得依赖本机残留的外部头文件或已构建归档。
其他子模块版本保持，除非另有独立授权的变更。

R03. 删除三项可选后端配置、互斥选择、`add_subdirectory`、编译定义、链接目标、
安装目标、导出文件及 `find_dependency` 分支。
若保留 `DAL_CPP_AAD_BACKEND` 包元数据，其值固定为 `Native`，不再用于选择实现。
安装消费者只通过 DAL 导出目标获得剩余依赖和诊断定义。

R04. 旧配置显式开启 `DAL_USE_XAD_AAD`、`DAL_USE_CODIPACK_AAD` 或 `DAL_USE_ADEPT_AAD` 时，
配置阶段报清晰迁移错误，不得静默编译成原生实现。
显式 OFF 或默认未指定时使用原生实现。若为旧 OFF 保留兼容处理，集中在一个配置边界，
不创建可选择的后端、无效 export 或生产分支。
直接消费者传入旧启用宏也应在受支持的编译入口得到明确拒绝。

R05. 简化未发布 D03 实现：删除外部 scalar adapter、后端名称分派及仅表达外部差异的能力字段。
保留设置/累加 seed、按通道读取 adjoint、活动 root、清零及区间传播中确有调用和契约价值的薄层操作。
不要为未来重新接入构造插件、虚接口、空壳 specialization 或备用后端注册表。
原生向量宽度、诊断状态和未实现的嵌套/高阶/反向事件能力按实际需求表达。

R06. 移除例子与 benchmark 对 XAD、CoDiPack、Adept 的显式 include 和链接，
特别检查 `dal-cpp/examples/aad`：现有原生配置仍显式使用 XAD，不能仅删库后关闭这个示例。
保留有用的原生 AAD 演示，用被动计算、解析梯度或有限差分进行教学对照。
其他示例的重复外部后端 CMake 链接分支删除，原生示例继续构建运行。

R07. 清理 Linux/Windows 构建脚本、Python 原生构建与 wheel 路径、CI 配置及其汇总 gate。
删除外部后端矩阵和 CoDiPack 专属线程隔离 job；同步删除 `needs`、环境变量和汇总结果引用，
使现有受保护检查入口能正确汇总新的原生任务。
原生 GCC/Clang/MSVC、诊断 OFF/ON、sanitizer、静态分析、生成完整性、绑定及安装消费者检查保持有效。
检查数量可以因移除外部任务减少，不能通过删除原生检查或扩大性能阈值取得全绿。

R08. 将适用于原生的测试解除外部后端条件保护。
外部库专属测试可随实现删除；共享数学测试、重复 sweep、别名播种、前缀累计、异常恢复、线程退出、
非有限导数及向量零通道测试保留。
失去跨库对照后，用解析、有限差分和原生标量/向量独立结果维持正确性证据，不能以互相调用同一实现替代 oracle。

R09. 诊断仍默认 OFF。OFF 不新增逐节点字段、所有权检查或注册表；ON 布局定义继续 PUBLIC 导出，
保证库、头文件、Python/Excel 和外部安装消费者一致。
原生单输出默认路径不增加能力查找、动态分派或错误消息构造。

R10. 实现完成时更新当前态安装、架构、AAD 方法、示例与构建说明，并增加外部后端移除的 CHANGELOG 条目。
更新本次活动规格与计划，使后续新功能不再要求外部后端验证。
保留书籍/算法参考和旧性能报告中的历史名称，不把它们误写成当前支持列表。
不编辑 `CLAUDE.md` 或 `.claude/`；需要涉及共享原始说明时报告具体待同步位置。

R11. 原生基线/head 独立构建、源码与二进制冻结后，执行既有九项配对性能门禁及受影响生产 MC/LSM/曲线案例。
保持两轮各十次、4% 阈值、路径数、线程数及归约规则；剩余依赖版本与原生编译配置匹配。
三项外部依赖只从 head 移除，历史 baseline 保持完整。
smoke 和此前 D02 性能通过不能替代 D00/D03 新提交的性能验收；保留失败与复核记录。

## 实施顺序

1. 冻结并保留既有发布提交和本地未发布成果；先建立原生数学及旧配置拒绝的失败证据。
2. 在独立逻辑提交中移除生产分支与三项依赖，同步修复构建、导出和依赖外部库的示例。
3. 简化 D03 原生操作与能力声明，保留已验证的 seed、通道和生命周期行为。
4. 清理测试、脚本、CI 和当前态文档，核对汇总 gate 与安装消费者。
5. 从不含三项外部依赖的全新源码完成原生 OFF/ON 全套验证，再冻结测量。
6. 完成性能验收、最终审查与当前提交 CI 后，进入后续市场及组合风险阶段。
