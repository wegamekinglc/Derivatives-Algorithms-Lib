# Owning Early-Exercise PDE Risk Worksheet

Load the DAL XLL. Use separate `Inputs`, `Summary`, `Risks`, `Scenarios`,
`Plan` and `Execution` sheets so spills do not overlap. Inputs are headerless;
output tables contain a header. Formulas below use comma separators.

On `Inputs`, enter:

| Cells | Contents, in range order                                                      |
|-------|-------------------------------------------------------------------------------|
| A1:A5 | `evaluation_date`; `maturity_date`; `strike`; `option_type`; `exercise_style` |
| B1:B5 | `=DATE(2026,10,18)`; `=DATE(2027,10,18)`; `100`; `PUT`; `BERMUDAN`            |
| D1:D2 | `spot`; `volatility`                                                          |
| E1:E2 | `100`; `0.2`                                                                  |
| G1:I1 | `=DATE(2027,10,18)`; `0.05`; `0.03` (end date, decimal rate, decimal yield)   |
| K1    | `=DATE(2027,10,18)`                                                           |
| A8:B8 | `upper`; `400`                                                                |
| D8:E9 | `delta`, `=TRUE()`; `gamma`, `=TRUE()`                                        |
| G8:H8 | `0.0001`; `0.0001` (coarse rate and yield bumps)                              |

Construct handles in dependency order:

```text
Inputs!M1 =EARLYEXERCISEPDESETTINGS.NEW("price-settings",A8:B8)
Inputs!M2 =EARLYEXERCISEPDEREQUEST.NEW("valuation",A1:B5,D1:E2,G1:I1,K1,M1)
Inputs!M3 =EARLYEXERCISEPDERISKSETTINGS.NEW("risk-settings",D8:E9,G8:H8)
Inputs!M4 =EARLYEXERCISEPDERISKREQUEST.NEW("risk-request",M2,M3)
Inputs!M5 =EARLYEXERCISEPDERISKRESULT.NEW("risk-result",M4)
Summary!A1 =EARLYEXERCISEPDERISKRESULT.GET.SUMMARY(Inputs!M5)
Risks!A1 =EARLYEXERCISEPDERISKRESULT.GET.RISKS(Inputs!M5)
Scenarios!A1 =EARLYEXERCISEPDERISKRESULT.GET.SCENARIOS(Inputs!M5)
Plan!A1 =EARLYEXERCISEPDERISKRESULT.GET.PLAN(Inputs!M5)
Execution!A1 =EARLYEXERCISEPDERISKRESULT.GET.EXECUTION(Inputs!M5)
```

The maturity-only Bermudan put is a COMPLETE control: five available risk
rows and 17 successful scenarios with the default 401-node/500-step grid.
Read `PriceAvailable` independently of `RiskComplete`. Risk columns include
`RiskId` (2), `Value` (10), `Status` (11), `Reason` (12), `Unit` (9) and
`Interpretation` (14). Every row needs its own availability check. Only
`AVAILABLE` and `AVAILABLE_EXERCISE_REGION` have a readable scalar value:

```text
=IF(OR(Risks!K3="AVAILABLE",Risks!K3="AVAILABLE_EXERCISE_REGION"),
    EARLYEXERCISEPDERISKRESULT.GET.RISKVALUE(Inputs!M5,"Gamma"),"unavailable")
```

Gamma is a finite-scale model approximation, with coarse/fine bumps shown
in each row. Vega is per decimal volatility; multiply by 0.01 for a vol-point
exposure. Rate/yield rows are native carry-parameter partials. Rate ×1e-4
is first-order parameter P&L for 1bp, without calibrated quote DV01 semantics.

For a deterministic PARTIAL worksheet, copy the workbook and change B5 to
`AMERICAN`, E2/H1:I1 volatility/rate/yield to zero (keep G1 as the maturity
date), and clear K1. Add `max_work_units`, `0` at A9:B9 and pass A8:B9 to M1.
Replace D8:E9 with `max_scenarios`, `1`; `max_work_units`, `0`.
Leave G8:H8 unchanged. Base price remains readable, one scenario succeeds,
and solves/work are zero. All five risk rows have
`UNAVAILABLE_DEGENERATE_DIFFUSION` and blank Value cells. Calling the scalar
Gamma getter directly returns `EarlyExercisePdeRiskValueUnavailable` Error
text. A blank risk value never means zero.

For smooth American exercise retain nonzero volatility/rate and use an
empty exercise-date argument. For two carry segments use two G:I rows ending
exactly at maturity and two matching bump rows; date axes retain input order.
Risk keys and IDs use exact canonical ASCII case. Omitted or entirely blank
bump columns default independently; a hole in a populated column is invalid.

Requests/results own copied data. Getter tables detach and perform zero new
solves; releasing source handles cannot change an existing result. Native
byte/work budgets apply cumulatively, and exclude worksheet copies and Excel
process RSS. Invalid input/preflight rejection preserves an existing output
handle; numerical failure still returns an inspectable result. Risk handles
cannot be archived. See the [method](../../docs/methodology/pde/early-exercise.md#owning-core-risk-request)
and [Excel contract](../../docs/excel/README.md#owning-early-exercise-pde-risk).
